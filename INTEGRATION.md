# AboEzzat client integration contract

## Android on-device Social Engine

The Android Social Engine app runs the extraction engine on the same phone as Share New and exposes a loopback-only API:

- Base URL: `http://127.0.0.1:8765`
- Health: `GET /health`
- Extract: `POST /api/v1/extract`
- Authentication: `Authorization: Bearer <token generated by the Social Engine app>`

The app binds only to `127.0.0.1`, so the API is not available to other devices on Wi-Fi. Start the Social Engine app and tap **تشغيل المحرك** before using extraction in Share New. Copy the generated token from the app into Share New's Social Engine settings. The token is stored in the app's private preferences and must not be shared.

Plain HTTP is acceptable only for this loopback endpoint because traffic stays on the same Android device. Any remote/LAN deployment must use a separately secured configuration and HTTPS or a trusted private network.

## Shared request and response contract

Send a POST request to `/api/v1/extract`:

```http
POST /api/v1/extract
Authorization: Bearer <private-service-token>
Content-Type: application/json
```

```json
{
  "url": "https://www.instagram.com/reel/EXAMPLE/",
  "cookies": "sessionid=...; csrftoken=..."
}
```

The `cookies` property is optional. Only send cookies belonging to the exact site being extracted. Never put cookies or the bearer token in logs, analytics, crash reports, or user-visible notifications.

## Successful response

```json
{
  "success": true,
  "platform": "Instagram",
  "title": "Example video",
  "thumbnail": "https://cdn.example/image.jpg",
  "formats": [
    {
      "url": "https://cdn.example/video.mp4",
      "quality": "720p",
      "type": "mp4",
      "headers": {
        "Referer": "https://www.instagram.com/"
      },
      "expires_at": null
    }
  ],
  "requires_cookies": false,
  "extractor": "yt_dlp",
  "error_code": null,
  "message": null
}
```

Example values above are illustrative, not live extraction results.

## Receiver handoff

Share New should choose a playable format, then send Receiver:
- the direct media URL,
- the format type,
- the non-secret request headers returned for that format,
- the title and thumbnail when available.

Do not forward the original page cookies or service bearer token to Receiver. The service bearer token belongs only between Share New and the extraction API. If a media CDN requires cookies, the current response intentionally does not forward them; this case needs an explicit, narrowly scoped design before enabling it.

## Failure handling

- HTTP 401: missing or invalid service token.
- HTTP 413: URL too long.
- HTTP 422: invalid request body.
- HTTP 400: invalid or blocked URL.
- `success=false`: extraction did not produce a playable format; do not send the page URL to ExoPlayer.
- `EXTRACTION_TIMEOUT`: allow one controlled retry, then stop.
- `NO_PLAYABLE_FORMATS`: do not send the page URL to ExoPlayer.

## Android implementation notes

- Run extraction off the main/UI thread.
- Use bounded timeouts and cancel requests when the user cancels.
- Do not log request bodies or Authorization headers.
- Keep API tokens out of source control.
- Receiver must use the returned headers when creating the ExoPlayer MediaItem / DataSource.
- For YouTube, Share New may route to the user's selected YouTube-compatible TV app instead of sending a page URL to ExoPlayer.
